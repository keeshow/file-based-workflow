# 2026-10-21-02

上一版：[2026-10-21-01](../2026-10-21-01/workflow/AGENTS.md)。

## 修改原因

实际项目整理长 Task 时发现：上一版虽已区分文档职责，但关键排查过程的保留标准、证据可获取性及旧文档精简边界仍不明确。Task 示例还要求形成故障结论后再整理 Note，容易使未结故障的过程继续堆积在 Task 中。

## 本版调整

- 明确 Note 可在根因未明时记录关键排查；Task 保留验收影响及后续行动，Handoff 保留项目摘要和入口。
- 补充重要信息的判断标准，区分失效待办与仍影响判断的历史验证事实，保留关键失败尝试及被推翻结论的原因。
- 证据说明适用版本、条件、保存位置和可获取性；临时文件不视为长期归档，缺失依据须标明并安排补验。
- 精简旧文档前核对重要信息的去向；普通修改经过由已提交的 Git 历史追溯，完整过程归档仅在明确要求时进行。
- 新增未结故障 Note 示例，同步 Task 和 Handoff 示例，展示同一问题的记录分工；示例均为虚构，不作为真实验证记录。
- 区分排查记录（`debug-主题.md`）与专题笔记（`note-主题.md`），示例文件采用相同前缀；补充类型标识、维护方式和专题笔记示例，不要求同一问题生成两份文档，也不自动将排查记录改写成专题笔记。
