# Debug 与 Note 写法

> 编写排查记录或专题笔记前阅读。何时创建以及专题笔记的生成权限见 `AGENTS.md` 第 6 节，本文说明具体写法。

## 排查记录（Debug）

- 文件命名为 `debug-主题.md`，开头标明“类型：排查记录”、状态及关联 Task。状态为排查中、已定位、已解决或暂停：根因已定位但尚未修复或复测时，不标为已解决；用户决定暂不排查时标为暂停，并写明原因。
- 服务于继续排查，可在根因未明时维护。生成条件见 `AGENTS.md` 第 6 节。
- 排除假设须限定适用条件；未复现不等于已排除或已修复，离线检查不能替代实际运行验证。

### 结构

按以下顺序组织，各部分按问题和假设合并更新，不按测试轮次分节：

1. **现象与复现条件**：现象、适用版本、环境和触发条件。
2. **关键尝试与证据**：表格，每次改变判断的尝试或样本占一行，写版本、条件、结果与判断、证据位置及可获取性；不增加新信息的重复测试合并到已有行。
3. **已确认事实与待验证假设**：每个假设标明当前验证状态；被推翻的判断保留结论和原因。
4. **结论与下一步**：已定位的根因、修复措施和复测结论；未结时写下一步和证据缺口。

新的测试结果应更新对应假设的状态，并在证据表中增加一行，不追加整段过程。

### 拆分与结项

- 篇幅参考 6000 字左右；超出时检查是否混入了多个问题，按问题拆分并互相链接。参考值用于提示整理时机，必要内容可以保留。
- 已解决的 Debug 补充结论后不再追加；问题再次出现时新建 Debug，并链接原记录。
- 创建、拆分或状态变化时，同步更新 `docs/notes/README.md` 中的对应行。
- 参考 [Debug 示例](../examples/debug-download-memory.md.example)。

## 专题笔记（Note）

- 文件命名为 `note-主题.md`，开头标明“类型：专题笔记”，按需说明适用范围。
- 按主题整理知识、方案、原理或经验，说明结论及其限制，并列出实际参考的 Task、Debug、Handoff 或其他资料的链接及参考内容；不要求凑齐所有类型。
- 引用 Handoff 时注明所依据的更新时间或版本，其状态摘要不替代验证证据。
- 创建后在 `docs/notes/README.md` 中增加对应行。
- 参考 [Note 示例](../examples/note-download-memory-validation.md.example)。
