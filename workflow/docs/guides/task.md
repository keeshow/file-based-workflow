# Task 写法

> 创建或整理 Task 前阅读。必须遵守的规则见 `AGENTS.md` 第 4 节，本文说明具体写法。

## 内容

- Task 维护当前任务安排与验收依据，建议内容为：**状态、目标、范围/非目标、主要步骤及完成情况、关键决策、验收标准及结果、遗留问题、下一步和关联资料**。
- 约束按需记录，已有项目规则用链接引用。

## 写什么、不写什么

| 部分 | 写法 | 不写 |
| --- | --- | --- |
| 状态行 | 以“状态：”开头，紧跟状态值及一句简要说明，如“`状态：PAUSED（用户决定暂缓长期稳定性验收）`” | 各验收项的详细结果 |
| 主要步骤 | 按阶段划分，如定位、修复、回归 | 每次测试、每份日志各列一项 |
| 关键决策 | 结论加一句理由 | 决策讨论经过 |
| 验收表 | 每个验收项一行：结果、适用版本或条件、证据入口 | 逐轮测试的数据和过程 |
| 遗留问题 | 每个问题一句话加链接；需要排查的问题链接到 Debug | 排查过程 |

- 排查过程、逐轮测试结果和原始数据放在 Debug 或参考资料中，Task 只保留对验收的影响、结论和链接。
- 篇幅参考 4000 字左右；超出时检查是否混入了排查过程或逐轮记录，整理后再追加。参考值用于提示整理时机，必要内容可以保留。
- `DONE` 或 `CANCELLED` 后不再追加内容；后续发现的新问题另建 Task 或 Debug，并链接本 Task。
- `PAUSED` 的 Task 在状态行写明暂缓原因，验收表中被暂缓的项标注“暂缓”。
- `CANCELLED` 的 Task 在状态行写明取消原因，如“`状态：CANCELLED（用户决定改用方案 B，见 [015](015-xxx.md)）`”；被新 Task 取代时，新 Task 也链接回本 Task。已完成的部分和未完成的验收项保持原样，不改写为通过。

## 步骤与验收

- 一个 Task 内按可检查的主要步骤管理实施进度，不按每轮对话、命令、函数或界面微调列项；仅在多个目标可独立验收时拆成多个 Task。
- 实施步骤的勾选只表示该步骤完成；验收按约定标准分别记录结果。
- 验收证据的记录方式见 [文档维护细则](maintenance.md)。
